## What changed (by README 6.9 item)

- **Entry/lifecycle** (`LootModule`): `Init` subscribes `LootSubstitutions.BeforeCreate` to `Hooks.CreateObjectEnter` (prefix) and loads the tables; `ProvideApis` provides `ILootTables` + `ILootSpawning`; `OnWorldReady` re-imports Patrols profiles when the file changed; `Shutdown` drops registered rules/runtime tables. Config: only `[Loot] Enabled` (bound by Core), no new entries, no migration (D12). No pages, no jobs (nothing periodic to run).
- **Natural loot substitution** (A7-9): moved from Survival. Same filters, same 1-in-4 roll on gas stove 2571597281285591657; the Stew Pot prefab (7392481500621300201) is resolved through the shared `Hooks.GetPrefab` resolver chain, which Survival answers while it runs -> the rule applies in exactly the situations the old Survival-owned hook did. Other modules can register `ILootSubstitution` rules (asked first). Publishes `NaturalLootSubstituted` (only when someone listens).
- **Loot tables** (`LootTableStore`): `config/WildWasteland/Loot/LootTables.json` (schema 1: tables with entries item/weight/min/max, `poiTables`, `lotTables`). Copy-missing import of the `carLoot`/`truckLoot` profiles of `PatrolsAndLoot.json` (looked up in `config/WildWasteland/Patrols/` then `plugins/WildWasteland/Patrols/`, where Patrols keeps it today); the Patrols file is never written. Profile item chance -> `LootEntry.Weight` (percent), Min=Max=1; `Roll` uses the Patrols `RollCount` rule. Writes through `AuthoringFiles.AtomicWrite` -> `AtomicFile.Replace` (D17); invalid files are preserved as `LootTables.invalid-*.json`. Assignments are empty (no new gameplay); nobody rolls these tables yet (Patrols keeps rolling its own profiles).
- **Spawner progress** (`SpawnerProgress`): the POI marker one-shot progress (ES3 key `WildWasteland.Towns.PoiDressMarkers.v1`, WWPM1, identity formula unchanged) now lives in Loot; the save goes through `SaveBus.Key(...).Write` (A6-8: cache now, re-save + StoreCachedFile + verify after the save, failure fails the save). Loading keeps the strict reader (throws -> POI blocks, as before). `PoiDressMarkers.Save/Load/Capture/Clear` (called by the POI entry) forward to it. It is static, so marker groups keep working when Loot is off. `ILootSpawning.TryProgress/ReportProgress/TryBudget` read/write it (owner key `PoiDressMarkers`, spawner path = marker identity; other owner keys are session-only). Publishes `SpawnerProgressChanged` on changes (only with listeners). `Progress` = fraction of the running marker spawn-list scan.
- **Native spawner control** (`NativeSpawners`): one copy of the ItemSpawner int helpers, budget capture, `Force`, `Apply` (the identical FSM rewrite loop of `Force` and `TownPopulation.Configure`), `Select`, `Resume`. Town/gas-station/marker partials call it.
- **Performance** (README 8 #5/#7 items in these files): `PoiSpawnCatalog` and `PickupCatalog` no longer run their own `Resources.FindObjectsOfTypeAll<PlayMakerFSM>` (shared Core `PrefabCatalog.AssetFsms`, same filter, same name sort for the catalog); the catalog's `ItemList` proxy lookup is cached per scan instead of a full `FindObjectsOfTypeAll<PlayMakerArrayListProxy>` per matching template; Cargo `Physics.RaycastAll` -> `RaycastNonAlloc` with a reused 64-hit buffer (file-map item); Cargo debug lines no longer build strings unless level 2.
- **Cross-module calls replaced**: Cargo `Register.Name/Add` -> Core `ItemSpawner.Name/AddExisting` (what Register forwarded to), `Patrol.FindChild` -> local copy (same search order), `PatrolsModule.Verbose` -> `Log.Deep`; Quests item query `QuestWorld.Items/All`, `FindInt/Float/String`, `HDist`, `UnderPlayer`, `BaseName`, `Util.Norm`, `Plugin.Info` -> Core `FsmIndex`, `WorldGeometry`, `PlayerState`, `Names`, local normaliser, `Log.Info` (L1 guard). Remaining POI/NPCAI/Patrols/Vehicles/Quests type uses are `refs-ok` with requests B15-1..4.
- **Logging**: `Log.Always` per POI marker group and per town roll -> `Log.Main` at level 1; NaturalLoot's `[Survival / Debug] VerboseLog` read is gone (level 2 `Log.Deep`).
- **D17**: the only file write Loot owns is LootTables.json (AtomicWrite). No `File.Replace`/`File.Move` in Loot.
