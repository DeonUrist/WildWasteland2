## Final architecture and behavior

- `WildWasteland.Core.Optimization.OptimizationRuntime` is a Core-owned singleton, not a registered gameplay module. B01 calls `Bind(settings, tools)`, `Instance.Init/ProvideApis/Shutdown` and the normal scene/world/save/load/origin callbacks. Its resource owner is the singleton (`Id = Core`), separate from null-owned Core dispatchers. The master is `[Performance / Preset] Enabled`; there is no `[Performance] Enabled` module hop or migration. Existing feature keys, preset enum values and individual tuning defaults remain.
- Replaced assembly-wide feature discovery with an explicit sorted list of **43 features**: all 42 concrete feature types under Optimization plus the existing DuplicateRigidbody feature adapter owned by B01 in Core/Fixes. Category/order/plan-id sorting preserves established feature ordering. No feature was omitted by the static registration audit.
- Moved all optimization types from the old Performance namespace into Core.Optimization. Split WorldSettings, EventDispatch, CameraCulling and PostFx into one file per feature. Framework, PlayMaker, Content, Rendering and World folders remain; there are no `_from*` folders in B02.
- Every method/nontrivial property in the package has a summary. Native callbacks describe the target and guard; common feature overrides document the lifecycle contract; helper summaries describe their concrete semantics. Logging uses guarded Core facade calls (L1 actions, L2 deep detail, warnings/errors retained), with no separate log policy or unguarded level-disabled formatting.

## Shared execution and correctness

- FS1 sleep now acquires/releases only `Core.FsmPause.FsmSleep`; it never writes ManualUpdate directly. PollSleep/CarLod/stepped reasons remain independent. Main-thread serialization wakes owned sleep claims; worker serialization no longer mutates the live ownership table. Shared Awake clears only copied, unowned pause flags.
- OnEnable, OnDisable, OnDestroy, Awake and the six 3D physics callbacks now use Core dispatchers for the previously duplicated optimization patches. Sleep wake and GUI cleanup handlers register before registry/physics replacement bodies, preserving reentrant enabled-FSM membership and cleaning GUI metadata before the native reference is cleared. Remaining unique wake sources retain their direct optimization-only patches.
- Shared RenderScan's CreateObject subscriber is registered **once** by the runtime instead of separately by LightPolicy and GeneratedLods. PollSleep's shared state-entry handler also registers once; its job restart checks `Job.Removed` directly instead of scanning all Scheduler jobs.
- Initial feature startup waits for a runner frame with a loaded scene or a scene-loaded callback. Plugin.Awake does not query a scene or touch RenderSettings through Optimization. Master off/on before that point retains the barrier; shutdown removes the startup job. Optional feature hook registration failures are isolated, including the early wake/GUI subscriptions.
- Runtime shutdown restores active features before removing only their owned jobs/hooks/patches, WorldTiles registration, ModAPI policy and FsmPause reasons. Shared registry/watch/poll-subscription flags reset so off/on re-registers correctly. Lifecycle dispatch ignores a stopped runtime.
- Fixed RenderScan's same-frame last-client off/on edge: clearing the final client invalidates `_requestFrame`, so immediate re-enable cannot silently skip the initial full pass.
- SaveGuard consumes typed BeforeSerialize/AfterSerialize/SaveEnd events and retains the native wait/isPlay early barrier for native save paths. A client enabled during an already-reverted save immediately restores its original values. Visual edits remain reverted until the native transaction releases them.

## Dependency removal and discovery

- Deleted PatrolsBridge and all reflection into Patrols cleanup types. Culler consumes `ICullingProtection` immediately before a far deletion; protection exceptions abort the current slice rather than deleting an unvalidated object. Correct-owner Patrols retention provider is coordinator wiring; no native cleanup thresholds/list order changed here.
- CarLod consumes `IVehicleOwnership` instead of inspecting component namespaces or detecting EngineSim itself. Native engine/player and physical joint/trailer exclusions remain. B01 owns the registry and coordinator wiring registers the actual ownership queries.
- Removed LightPolicy's 10-second global light scan. It receives the shared startup/world-ready and incremental scan; a cheap periodic prune only removes destroyed records. SunShadows is a light scan client and uses RenderSettings.sun plus the shared directional-light fallback, removing its five-second global scan/job. Exact original sun layer distances remain restorable.
- Generated LOD runtime uses `plugins/WildWasteland/Core/Optimization/LOD/` under D13. Deleted all direct Core calls/buttons into GeneratedLodExport; the coordinator moved authoring to Tools. GeneratedLodPack.Key/Hash remain usable by the Tools consumer. No installed/generated asset files were modified.

## Debug/statistics surface

- Public Core `IStatsSource` exposes feature plan id and cheap DrawStats. `Feature` implements it and the runtime exposes a cached read-only feature view for Debug controls.
- `OptimizationMetrics` owns the existing SendGo/SendGoChildren/SendGoFsm/Broadcasts/FastRemovals/Sleeps/Wakes/PickQueries/PickCasts counters and Reset. Debug subscribes to Marked for attribution tags; Core never calls a Debug type. Tag dispatch uses a copy-on-write observer array, allocating only on subscription changes rather than on every marked gameplay slice. Core native feature counters otherwise remain intact.
- PerformancePage now draws only the Core master and preset. B03 owns measurement/developer pages, telemetry lifecycle and the single frame/engine-counter collection pipeline.
