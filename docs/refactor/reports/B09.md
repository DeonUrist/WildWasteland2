## 3. Unification (goal 3)
- **Weapon catalog (P7)**: `WeaponCatalog` (IWeaponCatalog) is the single source of the gun-kind rule (ex Tracers.Classify and NPC
  WeaponRanges.Classify, identical text), the hold-style rule (ex PlayerBody Props.KindOfName, `Props.KindOf` delegates), the HUD caliber
  table (built from the catalog rows, same keys/strings/order), the `folk17` alias (PerGunAmmo) and the per-name multipliers that were
  hard-coded in MakeGun (crossbow x2.5, redmark 100/90, chopped pump shotguns 9 pellets/0.03/x1.5, full-length pump shotguns x2 range,
  applied with exactly the old conditions). Unknown names are classified on first use (same predicates), so modded names behave as before.
- **Stats (attachments-ready)**: `WeaponStats` (IWeaponStats) = catalog + config + ordered `IWeaponStatModifier`s. Gunplay applies the
  chain at fire time to range, projectile speed, pellets and damage multiplier (player, per item id) and range/speed/damage (NPC). With no
  modifier registered (the shipped game) `Modify` returns the value unchanged. Modifiers of stopped modules are skipped/pruned.
- **Hit pipeline**: Gunplay publishes `Hurt` (projectile hits, vanilla Bodypart.Damage incl. melee), `ProjectileHit`, `WeaponFired`,
  `VehiclePartHit`, `WheelPoppedOff` (see 4). VanillaHits no longer references HUD types (quiet rule = `GunplaySettings.ProjectilesEnabled`,
  output through `IHitFeedback`). Old service calls are kept until consumers switch (requests B09-6/7, single-delivery rule).
- **Overflow merge**: `OverflowTransfer` serves ammo (unit 1) and armor (unit 50 points); state machine identical to both originals.
- **Ironsights split**: projection already through Core CameraArbiter (B01); Gunplay keeps toggle + zoom target and publishes `AdsChanged`.
- **WeaponTransition split**: timing in Gunplay, publishes `WeaponSwitchPhase`; the lowering pose stays the Presentation partial (B09-5).
