## What changed (README 6.2 items)
1. **Lifecycle / jobs (goal 1).** The NPCAI entry now runs navigation: jobs `NPCAI.Nav`, `NPCAI.Passthrough` (0.25 s, game time), `NPCAI.PoiNav.Build` (sliced 500 us), `NPCAI.PoiNav.Traverse` (EarlyFixedUpdate), `NPCAI.PoiNav.Walkers` (WalkerTick is its own NPCAI job, README 6.2), scene reset, origin shift, shutdown (POI walkers/traversals released, passthrough pairs collide again, registries cleared). The old NPC-entry entry points (`Nav.Tick/OnSceneLoaded/Shift`, `Passthrough.Tick/OnSceneLoaded/Shutdown`, `PoiNav.BuildStep/WalkerTick/Shift/Reset`, `PoiNavTraverse.Tick`) are `[Obsolete]` forwarders that do nothing while `NavRuntime.Active` - so B07's NpcModule.cs (not B08's file) can still call them without double ticks/shifts until it drops them (B08-2). If the NPCAI module is switched off while NPC runs, the old path still works.
2. **One INavApi (goal 4).** Provided by NPCAI: `Structures`, `StructureAt`, `Discover`, `ForgetStructure`, `BakeIsolated` (PrefabCatalog lookup, one at a time, driven by the Nav job), `TryGetTemplate` (embedded pack / plugin vanilla / custom cache + PoiNav link count), `TryPath` (string-pulled grid route; straight line outside footprints; false when unmapped/unreachable), `TryFindCover` (Nav.CoverSpot), `RegisterOverlay/RemoveOverlay` (applied at phase 2 of a structure's bake; overlaid maps are never written to disk or kept as templates; register/remove rebuilds the map from its saved/template map), `RegisterWaypointProvider/Remove` (ordered chain consulted at the start of `Nav.Next`), `WorldGenerationSuspended` (backed by the shared `Services.PoiNavSetup` flag every current reader uses), `Revision`.
3. **Town routing without reflection or Harmony (P6, A6-9).** Removed: the Harmony prefix/postfix on `Nav.Next` (TownBakeBridge), Harmony postfix on `Nav.Make` + prefixes on `BeginBake`/`CreateMap` (TownOverlap), every reflection read/write of `Nav.Structure` fields and Nav statics (TownOverlap, TownTowerKit.Bake, PoiDressNavigation), reflection into `NpcModule` tuning fields and `Brain.Spawned`. Replaced by: two waypoint providers registered by `TownsModule.InitNavigation` (town routing, order 0, forced for approach detours/entrances = the old `Approach` flag; custom POI exits, order 100, taken when the body's way is clear = the old `TownNavigation.Clear` rule), internal Nav hooks (`Made`, `BeforeBake`, `MapWritable`, `AddMakeGate`) and typed access to `Nav.Structure` (same module now). `TownNavigation.Clear` forwards to the shared `Nav.WaypointClear` (identical code), `TownPaths.Heap` -> Core `MinHeap.Heap` (B01).
4. **LadderSpeed bug (README 9, A3-8).** The bind no longer rewrites a stored 1 to 2 on every start.
5. **D17.** Map writes already used AtomicFile; `PoiNavStore.Save` now keeps its `.bak` through `AtomicFile.Replace(tmp, path, path + ".bak")` instead of `File.Copy` over the old backup.
6. **Logging (D3).** `NpcModule.Log` adapter, `Log.Info/Always` and `[NPC]/[Towns]` prefixes replaced by `Log.Deep/Main/Warn/Error(owner, ...)`; every Deep/Main call that builds a string sits behind `Log.L2`/`Log.L1` (several Nav.Maps lines built strings at level 0 before). Town "connected/global blockers/instance bake kept/bridge installed" lines moved from always-on to level 1.
7. **Cross-module (goal 5).** `Services.Animation` -> `ModApi.Get<IAnimationApi>()`, `Services.Npc` checks -> `ModApi.Get<INpcApi>()`. Kept (Core statics, no provider yet): `Services.PlayerLadder*/LadderSlide*/LadderClimbers` (B08-8, waits for Presentation `ITraversal`).
8. **Dead code (README 7, goal 9).** `LearnLadderSide`/`MasksNow` were already gone (Wave A); removed `Nav.TemplateCount` (no reader), `TownNavigation.FailureReason` (never set or read, inventory world.md:280), the `TownBakeData` third map folder `plugins/.../NPC/NavMaps` (A3-1, D12) and the whole reflection layer listed in 3.

## Not done / proposals (Denis)
- **Nav sweep -> Core WorldIndex (A3-8 "Wave B work").** Not switched: WorldIndex reports each node once per scene without depth limit, while the Nav sweep (depth 4, stops at structures, retries inactive structures each pass, drops destroyed ones at pass start) would then also find structures nested inside structures and never see structures that were inactive when walked. Doing it needs an inactive-retry list, an "inside a known structure" ancestor check and a periodic dead sweep - a behaviour risk I did not want to take without your OK. Today's sweep costs <= 250 node visits per frame during a pass (passes every 2-15 s).
- **Town routing ownership (B08-6).** Town navigation classes still read POI's plan types (refs-ok). Recommended: POI owns them and registers through the INavApi providers/overlays B08 now offers.
