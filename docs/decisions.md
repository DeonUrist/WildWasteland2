## 2026-10-16 - Automatically disable replaced standalones through Apocasetter (Testing)

Denis requested that WW take priority over replaced standalone mods, with automatic disable via Apocasetter and a main-menu restart warning naming/counting the mods that should be removed from the active mod set. Core queues the existing installer's disable operation, retaining configs, recoverable plugin files and existing queued disable/removal requests. Already loaded mods have persistent runners/coroutines/patches and no common complete shutdown API, so the affected WW implementations wait until the next start. The installer then disables the source before chainloading and WW takes over. This supersedes the old manual-removal policy; it does not live-unload assemblies or change optional standalone compatibility dependencies. Shared folders are retained by disabling only the target DLL, shared DLLs require manual resolution, and unavailable installer/API/disk persistence produces explicit UI/log instructions. No new settings or Harmony targets.

## 2026-10-14 - CleanHUD is independent of Combat HUD
CleanHUD 1.5.1 (`119a2f8`) is ported into module `CleanHUD`, immediately after `HUD` in registration order. Combat HUD continues to own crosshairs and hit feedback; CleanHUD owns vitals, weapon/quick slots, strip compass, message log and title/pause menus. The standalone CleanHUD GUID is a soft dependency and conflict, never another plugin class. F7 Game / HUD exposes its player controls; the cheat-menu switch stays in Debug. Its public compass types retain class names under the documented `.Api` namespace; standalone `CleanHUD.Api` consumers require migration, no compatibility shim is registered.

DLL key scanning is background-only without joins; scene FSM/key discovery and modded icon CPU work use 500 microsecond scheduler slices. Scene paths, hidden UI, slot FSM variables and unchanged text values are cached. Native images decode once at module startup. Runtime-generated icons appear when their queued render finishes. Slicing cannot preempt a Unity camera render, texture upload or GPU readback; those first-use costs require an in-game measurement. No standalone baseline was available locally, and agents must not run the game.

## 2026-10-13 - Modules keep their original class names and nested structure
Every ported type keeps its class name and nesting (`Crew`, `Patrol+CorpseEject`, `Motorcycles.MotorcycleBalance`, `WarRig.WarRigUnit`, ...); only the namespace changes to `WildWasteland.Modules.<Id>` (plus the documented sub-namespaces `.Motorcycles`, `.WarRig`). Why: Easy Save 3 stores component types as `Namespace.Type, Assembly`; `Core.SaveTypes` maps the old assembly + namespace prefix to the new one by a **pure prefix rename**, so old saves with Apocapatrol / War Rig components load without a per-type table. Rules out: renaming or moving classes that can end up on saved objects, and one module spanning several namespaces. Documented gap: third-party mods that find the old types by reflection (`NPCAI.Api`, `Apocaplayer.ModAPI`, `Gunplay.Api`, `GunplayHUD.Api`, `Apocapatrol.*`) no longer find them; the absorbed consumers use `Core.Services`; a shim is only written when a real consumer appears (docs/modules.md 1.4).

## 2026-10-13 - Per-module Harmony ids created only by Core
Instead of literally one Harmony id, `Core.Patches` owns one `Harmony` instance per module (`<GUID>.<Id>`) plus the GUID itself for the shared dispatchers and Core patches. Why: a module switched off at runtime (F6 / F7 / error isolation) is unpatched with `UnpatchSelf` on its own id without touching the others. Rules out: `new Harmony(...)` or `PatchAll` anywhere outside `Core.Patches`; direct patches of a target another module also patches (`Patches` logs `CONFLICT`, reported in the startup summary).

## 2026-10-13 - Shared targets go through Core.Hooks with HarmonyX semantics
Every PlayMaker / Fsm / ES3 / FloatingOrigin target used by more than one module is patched once by a thin forwarder in `Core.Hooks`; modules subscribe handlers in Init and Core removes them on Shutdown. Semantics are exactly those of separate HarmonyX plugins: all prefixes run in module init order, the original is skipped when any returned false, postfixes and finalizers always run - so the ported handlers behave as they did as standalone mods. A dispatcher is patched lazily (`ApplyUsed`) only when a running module subscribed. Rules out: a module depending on another's prefix having skipped (handlers must stay independent except for the documented NPC-before-Guns shot counting order).

## 2026-10-13 - tools.cfg (F7) vs main cfg (F6) and "one toggle per feature"
Player-facing gameplay settings and all hotkeys live in the plugin's own cfg (shown by Apocasetter on F6; sections `<Id>`, `<Id> / <Sub>`, `[Keys]`, `[Debug]` last). Tuning constants, offsets, poses, editor switches and debug options live in `BepInEx\config\WildWasteland\tools.cfg`, invisible to Apocasetter and edited from the F7 tool window (`Core.UI.ToolWindow`, `ConfigPage`). Every player-visible feature has exactly one on/off toggle in F6 (bound first, in feature order; target <= ~25 F6 entries per module); the old mods' hidden never-saved settings became real tools.cfg entries with unchanged defaults. Rules out: never-saved `ConfigFile`s, orphan purges / `Config.Clear()` / `SettingsLayout` re-ordering on the shared files (they would damage other modules' entries), tuning values in F6.

## 2026-10-13 - Hotkey policy
Editor and debug keys default to `Key.None` and are reachable from an F7 button or toggle instead (Patrol editor, Template recorder, Bus passenger pose editor, Merchant item editor, NPC test web, Weapon pose editor). The old defaults `Insert` (bus pose editor), `NumpadMultiply` (merchant spotter) and `F9` (test web = the game's hide-UI key) are not carried over; an old binding is migrated only when the user had changed it from the old default. Gameplay keys keep their defaults (Observe LeftAlt, cassette Z / Minus / Equals, shout Q + LeftAlt, unload fallback R). F7 (`[Keys] Tool window`) is Core's key; all keys are InputSystem `Key` entries in `[Keys]` so Apocasetter rebinds them and `Core.Hotkeys.CheckConflicts` reports duplicates and game keys (F2 / F9 / F11). Rules out: `KeyboardShortcut` / string keys, polling `Keyboard.current` for top-level hotkeys outside `Core.Hotkeys` (editor-internal numpad polling inside a running editor is fine).

## 2026-10-13 - Runtime Enabled off/on is supported; Init is re-runnable
`[<Id>] Enabled` can be switched at runtime from F6 or the F7 Modules page: off runs `Shutdown()` (undo every game-state side effect) and Core removes patches, jobs, hooks and hotkeys; on runs `Init()` again (statics reset at the start of Init or in Shutdown; AssetBundles stay loaded because Unity refuses a second load). A failed Init runs Shutdown (safe after a partial Init) and can be retried from the toggle. Rules out: Init-time caching that is not reset, per-object components that keep running after Shutdown (they check the module's `Running` flag or are destroyed).

## 2026-10-13 - Conflict policy: module stays OFF while the standalone mod is present
At startup every module checks `Chainloader.PluginInfos` for its `ConflictsWith` GUIDs (soft `BepInDependency` on each so they load first). If one is loaded the module stays `OffConflict` (not started, no patches), the log names the DLL to remove, and the F7 Modules page / startup summary show it. WW never patches or disables the other mod and never registers a standalone mod's GUID (Apocasaver's participant adapters bind by name on `com.denis.apocalypter.apocapatrol` and would throw on every save if a plugin with that GUID lacked the exact private members). Rules out: "taking over" a running standalone mod (Gunplay's old `UnpatchSelf` of Apocaunloader), second plugin classes for save-compat GUIDs unless documented here.

## 2026-10-13 - Error isolation: per job (20 / 10 s) vs per module (40 / 10 s)
`Core.Scheduler` isolates every job: 20 exceptions in 10 s switch **that job** off (`job 'X' threw 20 times in 10 s - job DISABLED`, "(off)" on the F7 Performance page) while the rest of the module keeps running - the source mods' runners also swallowed a subsystem's exception per frame and went on. Only hook-handler and lifecycle-hook exceptions (game FSM paths, `OnSceneLoaded` etc.) count towards the module-level rule: 40 in 10 s -> `Stop(DisabledAfterErrors)`. Job errors are still counted and the first 5 per module are logged with stack. Why: with ~15 every-frame jobs per module one benign main-menu exception disabled whole modules within a second. Rules out: letting a job exception reach the Unity loop or disable a module.

## 2026-10-13 - Save data formats kept verbatim
Every module writes exactly what its source mod wrote: ES3 key `Apocapatrol.Patrol` (schema 14, magic `APOC`, base64 of the binary sidecar) + sidecar `config\WildWasteland\Patrols\Saves\<slot>.bin`, ES3 key `Apocaunloader.Magazines` (`...|1`) written to the ES3 cache after `SaveAll("global")` and in the `StoreCachedFile` prefix, NPC senses sidecar `<slot>.senses.txt` (`v1`), ES3 prefab ids 735710202610050001 (motorcycle) and 735710202610090001 (War Rig). Old sidecar locations stay readable. Why: saves made with the standalone mods load in WW and vice versa, and Apocasaver's retention rules (`Apoca*` keys = `Mod`) keep working. Consequence: a save made with WW loads **without** WW exactly as a save made with the standalone mods loaded without them - fine except objects whose components or prefabs came from the mods (motorcycles, War Rigs, raider crews / `Crew`, `Pilot`, `WarRigUnit`...), which the game cannot resolve (same as before). The SaveBus JSON sidecar (`<SaveGameN>.json`) planned in AGENTS.md is not used by any 0.1.0 module. Rules out: migrating keys to a `WildWasteland.*` prefix, dropping the old readers before one full release.
