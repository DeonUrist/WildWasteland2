## Cause and changes

- `Core.LoadingProgress` already has a module preparation source interface, but Towns never registered one. It therefore reported its native final-wait fallback (98%, preparing control) while `TownsModule.BeforeHandoff` legitimately held that wait. Towns now registers/removes a source at module Init/Shutdown. It reads completed lots, wall sections, tower bake/placement, border dressing, cached gate-graph rows, map/path preparation and resident readiness. The screen shows the current Towns stage, ready/total towns and **overall loading percent remaining**, matching the existing 70–98% preparation band. This is completed work with phase weights, not an elapsed-time estimate. Geometry and resident prerequisites retain their reserved work until completed. No Core or CleanHUD change, new polling job, native patch or change to the loading hold.
- Earlier bends were still derived from four bounding-box sides. The new reusable outline is a convex envelope of actual rotated building footprints with 7 m local clearance, plus the eight fixed cardinal-gate endpoints. It cuts empty corners and follows the outer building arrangement. It does not create concave alleys between buildings. Four 15 m cardinal openings, native signs, close exterior east parking and saved buildings remain fixed. Runtime walls, pedestrian graph and vehicle gate graph share the same contour; cached gate graphs use the actual number of contour vertices instead of four rectangular corners. The existing sliced adjacency/Floyd construction remains; no full-town bake or additional job.
- Towers use safe positions along the real contour, prioritized toward distinct corner quadrants, with ladders facing town. Candidate checks retain building clearance, gate approach clearance and spacing from previous towers. Large means at least eight non-parking, non-skipped buildings, or a frame of at least 10,000 m²; these request 3–4 towers, smaller towns retain 1–3. An impossible safe placement logs a warning and skips that tower instead of spawning it inside a building. Static dressing candidates must now be inside the actual perimeter.
- `TownNames.Assign` used a fixed coordinate/key hash then a sequential search. New unnamed towns now sample uniformly from unused entries with a per-session random generator, retaining cross-town uniqueness and the existing exhausted-pool fallback. Saved town names retain their identity. Names remain at `E:/SteamLibrary/steamapps/common/Apocalypter/BepInEx/config/WildWasteland/Towns/Names/` (not plugins): `Coyotes.txt`, `Scrapyard.txt`, `Animals.txt`, `Mutants.txt`. One name per line; blank lines/comments/duplicates ignored. Existing lists are never overwritten. Restart after editing. Small twelve-name defaults still naturally recur across different worlds; adding names expands the pool.
- Paths version 6 regenerates contour-aware links on older town plans; TownStore binary version remains 6, generator 9/layout 8. Buildings/native saved loot/residents are not relocated. Old DLLs cannot read newly written paths6 sidecars.
