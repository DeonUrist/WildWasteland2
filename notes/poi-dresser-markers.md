## Gameplay and list selection

- Hiding areas publish five floor-level `Hide`-tagged points (centre/corners) for native/WW NPC cover discovery. This is NPC cover authoring; it does not invent player invisibility or a new hiding-state system.
- Exits are doorway waypoints: arrow points out. The existing TownBakeBridge redirects an inside-to-outside navigation request through an authored exit; existing Nav/PoiNav still checks/routes the walk. Exit markers are not teleporters, basement doors or vehicle exit triggers. Sites without exits take the cheap empty-list branch.
- Item profiles: **All loot**, **Supplies**, **Weapons & ammo**. Car-part profile: **Car parts**. These filter the native `ItemList` indices and retain the source ItemSpawn_V1_All selector weights. The original native list contains equipment, supplies, weapons/ammunition and vehicle components. Classification uses native tags/layers plus model names; All loot includes car parts as vanilla does.
- NPC/monster profiles: **Animals**, **Mutants**, **Scrapyard**, **Coyotes**, plus canonical native **EnemySpawn_Wild_V1**, **EnemySpawn_Wild_V2**, **EnemySpawn_Scrapyard_V1**, **EnemySpawn_Coyotes_V1** lists when present. Faction profiles filter the first matching canonical native weighted list, rather than inventing new creature assets. Excludes boss/merchant/mechanic prefabs and BossUI-bearing actors, storm and boss/attack-wave spawner templates. Other native town population/faction pool logic is unchanged.
- Marker ID + stable POI type/world XZ identify each instance's one-shot progress. Chance/count and randomized XZ points within the marked floor area are seeded from that identity; nearby floor ray projection adjusts points when ground is found. Native FSMs choose *what* via their weighted selector, randomize the spawned item and perform normal naming/save-list registration. Author must place areas on clear, standable floors; this does not implement capsule-clearance packing for every species or prop shape.
- All markers of one custom POI share the existing arrival latch: approaching a registered group within 50 m queues the location. Marker groups wait for dressing completion. Existing Population WorldWork admission and .15 s actor/event spacing govern the native loop. Count/progress is restored before enabling native logic. Existing completed/killed/picked-up actors/items are not recreated. Newly added/copied markers receive fresh GUIDs; editing an existing marker does not reset its committed spawn progress/count.
- Custom gas-station item/car-part markers replace the hardcoded four default loot groups on newly constructed instances. Already spawned native loot is retained; live editing does not delete items. Default loot remains for layouts without authored loot markers. Existing default gas-station enemies remain disabled; authored monster markers explicitly enable their own groups.

Layouts write version 2; version 1 remains readable. Atomic publication/readback and `.bak` retained. Older DLLs cannot read newly written v2 layouts; preserve the backup if downgrading. Marker progress is a separate optional `WildWasteland.Towns.PoiDressMarkers.v1` key inside the same ES3 world save transaction, with AfterSave disk readback/failure reporting. The town-record format remains unchanged. No live layouts or saves were edited during implementation.
