# Wild Wasteland 1.0.4 — Save reliability

Saves now wait for pending terrain generation and application to finish before writing, then hold terrain streaming until save publication completes. Pausing game time alone did not stop MapMagic.Update: moving locations during serialization tripped the consistency guard and subsequently disabled saving. This affected standard WW and WWMP independently of Towns. The guard remains; the race is prevented at the save boundary.

Location discovery saves and journal publication now use a same-directory Windows replacement rename instead of Mono File.Replace, which failed with Win32 error 1175 in the supplied player log. Verified staging and journal rollback remain in place. Save controls stay visible, with their existing availability/status checks, rather than disappearing after a failure. Preparation cancellation/timeout releases input, time and streaming without starting a write transaction; actual write failures still report their error and retain consistency protection. New named saves remain separate files; only explicit overwrite targets an existing named save.

No new settings, save identities or formats. Two Core prefixes run a boolean check outside saves; pending terrain drains under the existing native application budget. Restores the accepted camp/building icons in the runtime package so updating no longer replaces them with older artwork. No personal configs or saves are modified or bundled. Unrelated pending wiki work is excluded.
